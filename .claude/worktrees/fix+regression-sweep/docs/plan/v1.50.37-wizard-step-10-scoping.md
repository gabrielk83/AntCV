**Status:** discovery only. No code change in this PR. Phased plan

## What "step 10" actually is, today

The wizard system is split across **four** sidecars and **app.js**.
A first-run user sees a modal sequence rendered by app.js's React
bundle plus an overlay slide injected by the sidecars at the end:

| File | Purpose | Lines |
|---|---|---|
| `pwa/app.js` (minified) | Wizard state machine, steps 1-9, navigation, persistence | sealed |
| `pwa/antcv-wizard-mode-bridge-337.js` | Bridges wizard's demo/own/byok choice → relay `/api/user/mode`. No UI. | 110 |
| `pwa/antcv-wizard-section-format-step10.js` | MutationObserver guard: shows the "Section formats" sticky card on step 10 only, hides it everywhere else. | 98 |
| `pwa/antcv-wizard-language-slide-339.js` | The actual final-slide modal. Renders: heading + blurb + primary-language radio + additional-languages checkboxes + section-formats read-only showcase + back/skip/continue. | 503 |

**Historical context:** the original step-10 content lived in
`pwa/antcv-onboarding.js`, retired in v1.40.303 (never loaded
in current `index.html`). The wizard-language-slide sidecar
absorbed its section-format showcase per the v1.40.339-j note.

## Persistence contract — preserve verbatim

Any port must keep the following localStorage writes intact, because
the legacy app.js and other sidecars read from them on every render:

- `language` — primary language (UI + content)
- `uiLang` — UI text only
- `enabledLanguages` — JSON array of `LangCode[]`
- `antcv:enabledLanguages`, `antcv:visibleLanguages` — mirror keys
- `antcv:prefs.enabledLanguages` / `.visibleLanguages` — yet more mirrors
- `personalInfo.stylePrefs.{enabledLanguages, visibleLanguages, languageBar}`

Plus the events:

- `storage` event (synthetic) for cross-tab
- `antcv:enabled-languages-changed` CustomEvent
- `antcv:language-changed` CustomEvent

Plus the one-shot `sessionStorage` guard.

## Why this is hard

1. **Wizard progression is owned by app.js.** The minified bundle
   decides when to call the language-slide sidecar's `buildModal`.
   The sidecar exposes `onContinue / onSkip / onBack` callbacks — those
   are the only contract points. Any React surface must hand the same
   callbacks back.

2. **The modal is at z-index `2147483647 !important`.** It sits above
   every other overlay (overlay sidecar, mobile bottom-nav, etc.). A
   React mount has to respect that layering or the wizard becomes
   unreachable.

3. **First-run is the only path.** Once `sessionStorage` flag is set,
   the modal won't show again until the user clears storage or starts a
   new session. Smoke-testing a port means clearing the flag + reloading
   on every iteration.

4. **Six storage keys for languages.** Any incomplete write desyncs
   the top-bar language switcher, the editor, and the worker fetch wrap.
   `writeLangsViaStabilityCore` is the canonical write path — the port
   must call it (or replicate every fallback in the right order).

## Phased plan

Each phase is a separate PR. Each phase keeps the existing wizard
working — no all-or-nothing flip.

### Phase A — v1.50.38 — Section-format showcase island (read-only)

Smallest viable cut. Replace the vanilla showcase tile grid (lines
~315-380 of wizard-language-slide-339) with a React-mounted island
that renders the same 7 tiles. No behavior change; pure visual port.

- New file: `src/islands/WizardSectionShowcase/WizardSectionShowcase.tsx`
- New mount: `src/islands/WizardSectionShowcase/mount.ts`
- Wizard sidecar tweak: instead of building the tile grid in DOM,
  add a `<div data-antcv-react-island="wizard-section-showcase"></div>`
  anchor inside the panel and call `mountAll()` after the panel
  mounts.
- Build: bundle grows ~2-3 KB gz.
- Risk: low. Read-only, no storage writes, no event listeners.

### Phase B — v1.50.39 — Language picker island

Port the primary-language radio + additional-languages checkbox
into a React island. Reuse the existing `LanguageCard` island's
storage helpers (`writeEnabledLangs`, etc.) so the persistence
contract is identical.

- New file: `src/islands/WizardLanguagePicker/WizardLanguagePicker.tsx`
- Wizard sidecar tweak: replace the inline radio+checkbox builders
  with an anchor + mountAll. Keep the `<h2>Set your languages</h2>`
  + blurb in vanilla (they're trivial).
- Risk: medium. Storage contract spans 6+ keys; must call
  `writeLangsViaStabilityCore` exactly.

### Phase C — v1.50.40 — Modal chrome + control flow

Port the backdrop + panel + back/skip/continue buttons. The
wizard sidecar shrinks to a thin bootstrap that listens for app.js's
"show wizard step 10" trigger and dispatches a CustomEvent the
React island subscribes to.

- New file: `src/islands/WizardStep10/WizardStep10.tsx`
- New CustomEvent contract:
  - `antcv:wizard-step-10-show` — open modal
  - `antcv:wizard-step-10-result` — `{ action: 'continue'|'skip'|'back', langs }`
- The wizard sidecar retires its `buildModal` function; just dispatches
  the event and listens for the result.
- Risk: high. This is the wizard's actual progression coupling. Need a
  feature-flag escape hatch (`localStorage.antcv:disable-wizard-step-10-react`)
  so a bad cut doesn't strand new users.

### Phase D — v1.50.41 — Interactive section-format picker in the wizard

Optional. Replace the read-only showcase with the live
`SectionFormatPicker` component so users can set per-section
formats during onboarding. Writes go directly to `layoutPrefs`,
so the editor honours the wizard choices immediately.

- Reuse `SectionFormatPicker.tsx` (already exists from v1.50.14).
- Compact mode (`compact={true}` prop) so 7 sections fit in a
  reasonable wizard slide height.
- Risk: low. Component is mature; just a different anchor.

## Out of scope for v1.50.37

This PR is **scoping only**. No JS / TS / CSS change. The deliverable
is this document.
