# v1.50.3 — SCE retry loop (≤2 retries; third draft returns flagged:true)

**Plan citation:** AntCV_Plan_v2_LockedSources.md §4.7 step 5 — "retry up to two times with an injected fix instruction; third draft returns with `flagged: true`".
**Branch:** `feat/v1.50.3-sce-retry` (stacked on `feat/v1.50.2-sce-ats-response`).
**Build version:** `1.50.3`.

## What this PR does

Generalises v1.50.2's `postProcessLlmResponse` into `executeSceWithRetry` and wires a provider-specific re-call closure into all four LLM paths. When the buffered response is dirty under SCE evaluation, the worker:

1. Builds a fix instruction listing the actual banned words / phrases hit.
2. Calls `reCallProvider(fixInstruction)` — a provider-specific closure that appends the fix instruction to the system content and re-invokes the upstream LLM.
3. Re-evaluates SCE on the new draft.
4. Repeats up to **2 retries** (3 attempts total).
5. After the final attempt, applies ATS glyph conversion (if `ats:true`), logs the eval to ANALYTICS KV, and returns the response with new headers:
   - `X-AntCV-Sce-Attempts: <1-3>`
   - `X-AntCV-Flagged: 1` (when the third draft is still dirty)

The fix-instruction format is the same `buildSceFixInstruction` shape `runWithSceRetry` uses, so the LLM sees a consistent retry prompt across paths.

## Per-provider re-call shape

| Provider | Body mutation | Endpoint |
|---|---|---|
| OpenAI | `messages[0].content += '\n\n' + fixInstruction` (system role) | `https://api.openai.com/v1/chat/completions` |
| Mistral | Same as OpenAI | `https://api.mistral.ai/v1/chat/completions` |
| Gemini | Deep-clones the gemini `payload`, mutates `systemInstruction.parts[0].text`, re-calls Gemini, **re-normalises** the response to OpenAI-shape so the eval helper sees consistent shape | `https://generativelanguage.googleapis.com/v1beta/models/${model}:generateContent` |
| Anthropic | `system` (top-level string) += fix instruction; body already has `stream:false` from the v1.50.2 stream-forcing | `https://api.anthropic.com/v1/messages` |

Any upstream failure during retry (rate limit, parse error, missing system field, etc.) returns `{ ok: false }` and breaks the loop — we keep the previous dirty draft and return it with `X-AntCV-Flagged: 1`. The request hot-path is never blocked by a retry failure.

## Cost model

Worst-case 3× LLM cost per generation (initial + 2 retries). The new `X-AntCV-Sce-Attempts` header and the `attempts` field in the `sce-eval` ANALYTICS event let analytics compute the actual cost distribution per (style × language). Expected steady-state: most generations clean on attempt 1 (attempts=1), a few retry once (attempts=2), rare third-draft (attempts=3 + flagged).

## Verification

Local smoke (run from repo root) — exercises clean-after-retry, persistent-dirty, and clean-first-try:

```bash
node -e "
import('./workers/proxy/src/writing-style-engine.js').then(async m => {
  const req = m.parseWritingStyleRequest({writingStyle:'nordic-minimal',target_language:'en'});

  let n = 0;
  const r1 = await m.executeSceWithRetry({
    data: JSON.stringify({choices:[{message:{content:'Strategic results-driven approach.'}}]}),
    shape:'openai_compat', writingStyleRequest:req, env:{}, userId:'t', augTask:null,
    reCallProvider: async () => { n++; return { ok: true, text: JSON.stringify({choices:[{message:{content: n===1 ? 'Strategic still.' : 'Focused approach.'}}]}) }; }
  });
  console.log('Clean on attempt 3:', { attempts: r1.attempts, flagged: r1.flagged, sce: r1.sce.bannedWordHits });

  const r2 = await m.executeSceWithRetry({
    data: JSON.stringify({choices:[{message:{content:'Strategic results-driven approach.'}}]}),
    shape:'openai_compat', writingStyleRequest:req, env:{}, userId:'t', augTask:null,
    reCallProvider: async () => ({ ok: true, text: JSON.stringify({choices:[{message:{content:'Strategic again.'}}]}) }),
  });
  console.log('Always dirty:', { attempts: r2.attempts, flagged: r2.flagged });
});
"
```
Expected: r1 attempts=3 flagged=false; r2 attempts=3 flagged=true.

Production smoke (after deploy):

1. Pick a style (e.g. nordic-minimal). Trigger a generation.
2. Response headers include `X-AntCV-Sce-Attempts` — usually `1`. If it ever shows `2` or `3`, the retry loop ran.
3. ANALYTICS KV: look for `writing-engine:<ts>` keys with `kind: 'sce-eval'`, `attempts > 1` — those are the retries.
4. Set a banned word that the LLM is likely to use (e.g. add "strategic" to a Danish bucket and generate in Danish). Watch the attempt count climb if the LLM keeps using it.

## Risk

- **3× cost worst case.** Mitigation: monitor `attempts` distribution in ANALYTICS for the first 1-2 weeks. If retry rates are higher than expected (>5%), the fix instruction may need tuning OR the SCE thresholds need reconsidering.
- **Latency.** Each retry adds the upstream provider's full request-response cycle. For Anthropic streaming was already disabled in v1.50.2 for writing-style calls; retries compound that latency. Acceptable trade-off — the alternative (returning dirty output) defeats the purpose of having a banned-list.
- **Idempotency.** Each retry re-uses the same `outBody` / `mistralBody` / `payload` / `bodyText` variable; the fix instruction is **appended**, not prepended, so the writing-style preamble from v1.50.1 remains the topmost system content. The fix instruction lands just before the model's final reply.
- **Provider rate-limits.** If the provider 429s mid-retry, `reCallProvider` returns `{ ok: false }`, the loop breaks, the previous dirty response is returned with `X-AntCV-Flagged: 1`. No request is dropped.

## Follow-up

- **PWA observability:** Surface `X-AntCV-Sce-Attempts` and `X-AntCV-Flagged` in the dispatcher breadcrumbs panel.
- **Adaptive retry:** If we observe styles or languages with persistently high retry rates, consider per-style retry-limit tuning (e.g. cold-outreach might only need 1 retry; research-formal might benefit from 2 even on first run).
- **§8.4 release-gate test:** With retry active, the violation rate per 100 outputs should drop. Re-run the §8.4 sample after 1-2 weeks of analytics to measure the post-retry baseline.
