# Generation Optimization — Ask The Right Things First (2026-06-22)

Owner brief: "lots of sidecars are used to patch issues generated by previous ones.
Check for optimization of the processes and cut some tweaking by asking the right
things first."

This report maps the generation pipeline, catalogs the post-hoc content-patching
sidecars, and states for each cluster what the generation step should ask for so the
patch becomes unnecessary. It is analysis only — no code was changed.

---

## (a) Pipeline map

Generation is **client-orchestrated**. The Cloudflare workers are dumb runners.

1. **Skeleton — `me()`** in `pwa/app.src.js:2967`. Returns the fixed `{cv:[...], cl:[...]}`
   section list with **legacy `type`s and bracketed placeholder strings as content**:
   - `profile` `type:"text"`, content `"[PROFILE — 2-3 tight sentences …]"` (line 2985)
   - `work_style` `type:"text_inline"`, content `"[Work style — 1-2 sentences …]"` (2994)
   - `outcomes` `type:"bullets"`, items `[{b:"[Verb]", t:"[concrete … outcome]"}…]` (2997)
   - `core_comp` `type:"table"`, rows `[["Focus Area","Strategic Expertise"],["[Focus area 1]", …]]` (3015)
   - `experience` `type:"experience"`, 8 placeholder roles `"[Role title]"/"[YYYY – YYYY]"` (3030)
   - `pubs` `type:"list_italic", richPub:true`, items `["[Publication, patent, …]"]` (3131)
   - `foundation` `type:"foundation"` (CL, line 3321); CL also `opening/who/why/contribute/closure`.
   The skeleton holds the **structure**; the LLM is asked only for **content fields**.

2. **Prompt — client-built.** The big generation prompt is assembled in `pwa/app.src.js`
   (`generate_cv` task; system prompt at `:23581`, no-JD prompt at `:23468`, Danish gate at
   `:23532`). It asks the model to return a **flat overrides JSON**, NOT typed sections:
   ```
   cv_overrides: { profile_content, work_style_content, outcomes_items:[{b,t}],
                   core_comp_rows:[[focus,exp]…], experience_roles:[{title,company,years,bullets,on}],
                   tools_items, certifications_items, education_items, publications_items,
                   regulatory_items, additional_items }
   cl_overrides: { who_content, why_content, foundation_hands_on, foundation_professionally,
                   bring_rows, contribute_intro, contribute_items, contribute_closing, closure_content }
   meta:{…}  rationale:{…}
   ```
   The prompt **never mentions `rich_block`, `richPub`, or any section `type`.** It speaks the
   old field vocabulary only.

3. **Worker — section-agnostic.** `workers/proxy/src/gen-job.js` (and demo-proxy twin) take
   `sections:[{id,title,prompt}]` and run each section's prompt, returning text
   (`runSection`, `:282`). `supervisor.js` runs a cross-section coherence pass. **No worker
   defines or validates section types** — `VALID_TYPES` lives only in the docx-worker for
   *export*, not generation. So the output contract is 100% client-side.

4. **Hydration — placeholder survives on miss.** The overrides are spread onto the skeleton
   sections conditionally:
   - `pwa/app.src.js:23025` — `"profile"===e.id && g.profile_content ? {...e, content:g.profile_content} : e`
   - `:23028` outcomes, `:23032` core_comp; second hydration path `:25471`, `:25607`;
     export-source path `:24317`–`:24450`.
   When a field is **absent or empty**, the ternary falls through to `e` — the **untouched
   skeleton section with its `[PLACEHOLDER]` content**. That is the mechanical root of both
   "placeholder text leaked into the export" and "section came out empty/placeholder".

5. **Post-hoc sidecar chain.** On `antcv:sections-updated` (and on load/cloud-restore) a long
   chain of `pwa/antcv-*.js` files rewrites the hydrated sections: type conversions, dedup,
   placeholder stripping, repopulation, dash/verbosity normalization. **88 files** touch that
   event. This report targets the subset that fixes *generation* defects (not pure UI).

### The two structural causes

- **Cause A — field vocabulary ≠ render vocabulary.** Generation emits `profile_content`,
  `*_items`, `*_rows` against legacy `type`s (`text`/`text_inline`/`bullets`/`table`/
  `foundation`/`list_italic`/`labeled_list`). The render/export truth is now `rich_block` +
  `richPub`. Six conversion sidecars (757–763) translate every load. Generation-native
  emission is **DEFERRED** (memory `rich-block-universal-section.md:19`): "high-risk +
  regen-gated; owner OK'd shipping with migrations as the mechanism."
- **Cause B — placeholder-as-default + thin output gate.** The skeleton placeholder is the
  fallback on any missing/empty field, and the bracketed authoring instruction is *also* used
  as the field's seed content. When the model echoes or appends it (observed live,
  SKELETON-LEAK-001), or simply omits a field, the instruction prints. The only gate today is
  a brace-balance/length check (`__antcvOutputInadequate`, `:1823`) that catches truncation,
  **not** per-field placeholder survival.

## (c) Top-5 "ask the right things first" — by patch-elimination payoff

1. **Generate `rich_block`/`richPub` natively (retires 6 conversion sidecars).**
   Teach `me()` to seed those section ids with `type:"rich_block"` (and pubs `richPub`), and
   change hydration (`pwa/app.src.js:23025`, `:24388`, `:25471`, `:25607`) to write the
   override fields into `items:[{b,t}]` shape instead of `content`/legacy shapes.
   **Retires:** `foundation-to-rich-block-758`, `text-sections-to-rich-block-759`,
   `hwic-to-rich-block-760`, `labeled-list-to-rich-block-763` (+ the parts of
   `publications-main-757` that re-type pubs). **Blocker today:** deferred because hydration
   speaks the old field vocabulary AND the docx export/preview readers were only recently
   taught rich_block; a regen is required to confirm. **Cost:** one schema rewrite, regen-gated.

2. **Kill placeholder survival at the hydration boundary (retires the leak + empties patches).**
   Two changes: (i) stop using the bracketed authoring instruction as the field's *seed
   content* — keep the instruction in the prompt only, seed the skeleton field with `""`;
   (ii) at every `g.field ? {...e,content:g.field} : e` site, the `: e` branch must fall back
   to a **clean empty render**, never the `[PLACEHOLDER]`. Add one `validateOutputContract()`
   pass after JSON.parse that flags any field still matching `/^\[.*\]$/` and rejects/repairs.
   **Retires:** `strip-skeleton-placeholders`, the placeholder half of `sidebar-repopulate-758`
   and `publications-main-757`. **Cost:** small, but touches the merge in 4 places.

3. **One output-contract validation + normalization pass after JSON.parse.**
   A single function run on the parsed `{cv_overrides,cl_overrides}` that: dedups
   `publications_items` and core/bring Focus Areas; strips section-label prefixes; sorts
   outcomes by metric and roles reverse-chron; assigns missing role `id`s; replaces `—/–`→`-`;
   schema-checks each section's required keys. This is where 10+ render-time sidecars belong —
   run once, deterministically, not on every `sections-updated`.
   **Retires:** `tables-core-dedup`, `publications-dedup`, `heading-label-dedup`,
   `outcomes-metric-order`, `experience-order`, `role-id-stabilize`, `emdash-to-hyphen`,
   most of `shape-guard`. **Cost:** medium; consolidates existing logic.

4. **Canonical-vocabulary prompt block (concise languages, no artifacts, no editorial verdicts).**
   Add an enumerated-vocabulary rule to the generate prompt (`:23581`): proficiency ∈
   {native, professional, intermediate, basic} with no variant tails; accessibility row =
   accommodation-only (ACCESS-NO-COMMENT-001 already drafted — enforce); forbid
   evidence-artifact phrasing. **Retires:** `languages-concise`, `accessibility-comment-strip`,
   `evidence-artifact-strip`, `ai-assisted-to-methods`. **Cost:** small, prompt-only.

5. **Enforce "INCLUDE ALL ITEMS / hidden-not-dropped" instead of re-deriving client-side.**
   The prompt already orders the model to return every sidebar item and every role with
   `on/hidden` flags (`:23581`). It is not enforced, so empties slip through and
   `sidebar-repopulate-758` re-derives from `personalInfo`. Make hydration **always merge from
   `personalInfo` as the base** and let overrides only set visibility/order — then a missing
   item is impossible by construction. **Retires:** `sidebar-repopulate-758`,
   `recs-as-list` (emit structured), `sections-normalize-415` placement half.
   **Cost:** small–medium.

## (d) Single structural recommendation

**Adopt one generation output contract + a deterministic post-parse pass; make the skeleton a
typed base, not a placeholder carrier.**

Concretely, three coupled moves:

1. **Typed contract.** Define the section schema (id → final `type` + required keys) in ONE
   place shared by `me()`, the prompt, and hydration. Generation emits final types
   (`rich_block`/`richPub`/`table`/`experience`/`education`), not the legacy field vocabulary.

2. **`hydrateContract(parsed, personalInfo)`** — a single deterministic function that runs once
   after `JSON.parse`, before the sections ever reach React/`sections-updated`. It:
   merges overrides onto a `personalInfo`-derived base (so nothing is ever empty); validates
   every field against the schema; rejects/repairs any `[…]` placeholder survivor; and folds in
   the normalization currently scattered across dedup/order/dash/label sidecars.

3. **Skeleton seeds empty, not bracketed.** Move the authoring instructions
   (`"[PROFILE — 2-3 tight sentences …]"`) out of `content`/`items` and into the prompt only.
   The skeleton field starts `""`; the placeholder can never print or be echoed.

This collapses **~15 content-patch sidecars** (every rich_block converter, every dedup/order/
strip/repopulate) into one validation function plus a typed schema. The render-time
`sections-updated` chain shrinks to genuinely interactive UI sidecars. It also removes the
boot-storm pressure (`sections-updated-damper`) those re-render-on-event patches create.

**Sequencing (regen-gated):** ship the post-parse pass first (items 2–5 above are low/medium
risk, no schema change) to retire the normalization sidecars; then take the rich_block-native
emission (item 1) behind a regen so preview/export parity can be verified live before the
conversion sidecars are removed.
