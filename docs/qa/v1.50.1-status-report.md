## How the end-to-end flow works after this PR

1. User opens the WritingStylePicker in Settings → Personal → Writing style and selects, say, Achievement-Driven with the `quantified` chip and a Danish banned word `tværgående`.
2. The picker writes `personalInfo.writingPrefs.style = "achievement-driven"`, `chips = ["outcome-led", "quantified", "scope-anchored"]`, `extraBannedWords.da = ["tværgående"]`.
3. The user clicks an AI-generation button. `pwa/app.js` calls `fetch(proxyUrl, { method: 'POST', body: '{"messages":[…],"system":"…"}' })`.
4. The fetch wrap installed by `src/lib/install-fetch-wrap.ts` intercepts:
   - Detects POST, JSON body, LLM-shaped (has `messages`).
   - Reads `personalInfo.writingPrefs` + `layoutPrefs`, builds the `_antcv_writing_style` payload.
   - Re-serialises body with the extension field added at the top level.
   - Calls `inner(input, newInit)` — the inner fetch is the chain through cloud-restore-filter, cloud-put-shrink-guard, kernel-completeness, and finally the native fetch.
5. The proxy worker (`workers/proxy/src/index.js`) receives the request.
   - `parseWritingStyleRequest(parsed._antcv_writing_style)` normalises the fields (legacy alias → canonical, clamp targetPages to allowed range, etc.).
   - `buildStyleSystemPreamble(req)` constructs the multi-line context (style identity, content rule, avoid rule, active chips, target language, target pages, ATS flag, integrity rules, language-bucket banned words/phrases).
   - The preamble is prepended to whatever system content was already there (whether Anthropic-style `system` field or OpenAI/Mistral `messages[0].content` or Gemini `systemInstruction.parts[0].text`).
   - The `_antcv_writing_style` field is `delete`d so providers don't reject the request.
   - Fire-and-forget telemetry to the ANALYTICS KV.
6. The upstream LLM call proceeds normally. Provider sees the enriched system prompt.
7. The response comes back. New `X-AntCV-Writing-Style: achievement-driven`, `X-AntCV-Target-Language: da`, `X-AntCV-Tone-Chips: outcome-led,quantified,scope-anchored` headers are attached.
8. The PWA renders the response. (No SCE retry on this PR — see "Deferred" above.)

## Risk

- **Proxy worker is production.** This PR adds ~100 lines to `index.js` between `augmentBodyText` and the injection-defense block. Wraps the whole block in `try/catch` — failure mode is "request proceeds without writing-style enrichment", never a crash. Deploy via `wrangler deploy` after review; `wrangler tail` confirms no errors in the first few real requests.
- **Fetch wrap is outermost.** Per CLAUDE.md, wrapping `window.fetch` again is the same pattern the existing three wrappers use. The wrap is **idempotent** (`__antcvWritingStyleFetchWrap` marker), so accidental double-install is a no-op. The body re-serialisation is the only mutation — no header or method changes.
- **Body shape conflict.** If some other proxy endpoint already uses `_antcv_writing_style` as a field name, the worker would mis-detect. Grep across `workers/`: no other usage of `_antcv_writing_style` or similar prefixed name. Safe.
