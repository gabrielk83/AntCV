## What this PR does

Adds a "Saved tones" section to the WritingStylePicker (between Tone chips and Target CV length). Users can snapshot the current tone configuration into a named slot and switch back later without losing the previous state. PWA-only — the worker schema is unchanged because slots live entirely in `personalInfo.writingPrefs.savedSlots[]` and aren't sent to the proxy at generation time.

## Storage shape

```ts
interface SavedToneSlot {
  id: string;             // crypto.randomUUID() with fallback
  name: string;           // user-given label (default "Slot N")
  savedAt: number;        // ms epoch
  snapshot: {
    style: StyleId;
    chips: string[];
    extraBannedWords: BannedBucket;   // { en, da, es, zh }
    extraBannedPhrases: BannedBucket; // { en, da, es, zh }
    extraConstraints: unknown[];
  };
}

personalInfo.writingPrefs.savedSlots: SavedToneSlot[]
```

Snapshots are tone-only. `targetPages`, `lineLimits`, `sectionFormats` (layoutPrefs), `package` (stylePackage), and `ats` / `legacyAtsTier` (exportPrefs) stay separate from the slot — switching slots changes voice, not visual or export defaults. This matches the plan's "Slots backing data: `personalInfo.writingPrefs.savedSlots[]`" wording.

## Helpers added (`src/lib/writing-prefs.ts`)

| Function | Behaviour |
|---|---|
| `saveCurrentAsSlot(name?)` | Snapshots current writingPrefs into a new slot. Default name is the lowest unused "Slot N". Returns the new WritingPrefs (with the slot appended). |
| `loadSlot(id, treatAsExplicit = true)` | Replaces tone state with the slot's snapshot. By default also flips `overrides.chips = true` so the worker's style cascade won't re-seed chips on later style changes. |
| `renameSlot(id, name)` | Trim-and-replace name. Empty name = no-op. |
| `deleteSlot(id)` | Remove the slot. Unknown id = no-op. |
| `normaliseSavedSlots(raw)` | Read-side filter; rejects malformed entries from a legacy or hand-edited `personalInfo.writingPrefs.savedSlots`. |

All four mutating helpers emit `antcv:writing-prefs-changed` (via the existing `writeWritingPrefs` path), so anything subscribed (PWA preview, Breadcrumbs panel) picks up the new state immediately.

## UI

`<SavedTonesEditor />` inside WritingStylePicker:

```
SAVED TONES
[ + Save current as new slot ]

[ Slot 1                       ] [Load] [×]
   Achievement-Driven · 3 chips
[ Senior, scope-heavy          ] [Load] [×]
   Prestige Structured · 4 chips
```

- **Save** appends a slot using the active style + chips + banned lists. Name defaults to "Slot N".
- **Inline rename:** click (or double-click) the name → input. Enter to commit; Esc to cancel; blur commits.
- **Load** replaces current style/chips/banned-lists with the snapshot. The legacy `cascade` re-seed of chips is suppressed via `overrides.chips = true`.
- **Delete** (×) — no confirm; reload from any other saved slot if it was a mistake.

Empty-state hint when no slots exist.

## Verification

After deploy:

1. Settings → Personal → Writing style → "Saved tones" section.
2. Click "Save current as new slot" → a "Slot 1" row appears showing the active style + chip count.
3. Click the name → input opens → type "Senior, scope-heavy" → Enter. The label updates.
4. Switch style to nordic-minimal in the dropdown, change chips, then click "Load" on the saved slot. The previous style + chips return.
5. Click × → the row disappears.
6. DevTools: `JSON.parse(localStorage.personalInfo).writingPrefs.savedSlots` reflects the current state with ids + snapshot bodies.

## Risk

- **Cross-tab consistency.** `writeWritingPrefs` already dispatches the `antcv:writing-prefs-changed` CustomEvent, so both the picker and any other open tab refresh on slot save / load / delete.
- **Snapshot drift.** The snapshot captures tone state at save time; if the registry's chip catalogue changes (e.g. a chip is removed), a stale slot may load a chip that's no longer compatible with its style. The picker's existing chip-conflict UI flags this; the slot itself stays loadable.
- **Schema migration.** `normaliseSavedSlots` filters out anything that isn't a valid SavedToneSlot at read time, so a malformed `savedSlots` array (legacy `unknown[]`, hand-edited JSON) silently degrades to an empty list rather than crashing.
