## What this PR does

Closes the last Pass 4 step. Three layers:

1. **Reusable `<SectionFormatPicker />`** (`src/islands/LayoutPicker/SectionFormatPicker.tsx`) — single-section row with a format dropdown (9 layouts from plan §4.4) + a 1-15 line-limit slider + a reset button. Reads / writes `personalInfo.layoutPrefs.{sectionFormats, lineLimits}[sectionId]`. Component is intentionally generic; the same row will mount inside the editor per-section in a follow-up that touches `pwa/app.js`.
2. **`<LayoutPicker />` panel** mounted in Settings → Personal — one row per known section (Profile, Core Competencies, Selected Outcomes, Experience, Tools & Methods, Certifications, Education, Publications & Patents, Additional Information). Provides a one-stop layout panel until the inline-editor surface lands.
3. **Worker wire-format extension** — the v1.50.1 fetch-wrap now sends `sectionFormats` and `sectionLineLimits` objects alongside the existing `sectionFormat` (single, kept for backward compat). The proxy worker's `buildStyleSystemPreamble` appends a "Per-section overrides" block that the LLM consumes when generating the named section.

## Storage shape

```ts
personalInfo.layoutPrefs = {
  targetPages: number,
  lineLimits:     Record<string, number>,   // sectionId → 1..15
  sectionFormats: Record<string, string>,   // sectionId → 'paragraph' | 'bullets' | 'unicode-bullets' | …
};
```

When the slider or dropdown is at its style-default, no entry exists in the map — the worker preamble falls back to the style's `sectionFormatDefaults` for that section.

The reset button (↺) deletes both entries for the section so it reverts to the active style's default. Disabled when no override is active.

## Default resolution

```ts
defaultLineLimitFor(styleId, targetPages) =
  round( base[lineDensity] × clamp(targetPages / 2, 0.5..2.5) )

base = { low: 3, medium: 4, 'medium-high': 5, high: 6 }
```

The number is intentionally coarse — the LLM interprets it relative to the section type (lines of paragraph for `profile`; bullets per role for `experience`; rows for `core_competencies`; etc.).

## Worker preamble — new block

When either map has entries, an additional block lands in the §4.7 preamble:

```
Per-section overrides (apply when generating the named section):
  - profile: format=paragraph, lineLimit=3
  - experience: format=bullets, lineLimit=5
```

Smoke-tested via `node -e` on the proxy worker module — the override block appears exactly when expected and absent when both maps are empty.

## What this PR doesn't do (deferred)

- **Inline editor surface.** The reusable `<SectionFormatPicker />` is positioned to also mount inline per-section in the editor (which lives in the minified `pwa/app.js`). Step 21's plan wording mentions "used in both the wizard and the editor." The Settings-panel surface ships first because it doesn't depend on app.js DOM anchors. A follow-up cut can mount the same component per-section inside the editor once a stable anchor convention is in place.
- **Wizard step-10 replacement.** `pwa/antcv-wizard-section-format-step10.js` (1100+ lines of vanilla JS) still has its own implementation. Replacing it with `<SectionFormatPicker />` is a careful refactor that should ship on its own.
