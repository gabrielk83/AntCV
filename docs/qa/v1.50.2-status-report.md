# v1.50.2 — response-side SCE evaluation + ATS glyph conversion

**Plan citation:** AntCV_Plan_v2_LockedSources.md §4.7 step 5 (SCE) + step 6 (ATS/Export).
**Branch:** `feat/v1.50.2-sce-ats-response` (off `main`).
**Build version:** `1.50.2`.

## What this PR does

After the proxy worker receives an LLM response, if the request carried a `_antcv_writing_style` payload (set by the PWA fetch-wrap shipped in v1.50.1), the worker now:

1. **Buffers the response** (forces `stream:false` on Anthropic; OpenAI / Mistral / Gemini already buffer).
2. **Extracts the generated text** from the provider-specific JSON shape.
3. **Runs the Semantic Constraint Engine** (`evaluateSce`) against the per-language banned base ∪ user extras. Case-insensitive word match; case-insensitive + punctuation-tolerant phrase match.
4. **Applies ATS glyph conversion** (`☎→Phone:`, `✉→Email:`, `🔗→Link:`, `⌂→Location:`, `★→Highlight:`) when `ats:true`.
5. **Logs the SCE evaluation** to the `ANALYTICS` KV namespace (90-day retention) as a `sce-eval` event — one per request, separate from the existing `writing-engine` selection event from v1.50.1.
6. **Attaches response headers** so the PWA + downstream observability can see the result:
   - `X-AntCV-Sce-Banned-Words: <count>`
   - `X-AntCV-Sce-Banned-Phrases: <count>`
   - `X-AntCV-Sce-Clean: 1|0`
   - `X-AntCV-Ats-Applied: 1` (only when ATS conversion actually changed the output)

Together these enable analytics queries like "violation rate per (style × language)" that the §8.4 release-gate test requires.

## What this PR does NOT do

- **SCE retry loop.** Plan §4.7 step 5 specifies up to 2 retries with an injected fix instruction; third draft returns `flagged:true`. The retry loop requires re-calling the upstream provider with a modified system message, which materially changes how each provider's response path works (different mutation semantics, different retry storms under rate-limit conditions). **Deferred to v1.50.3** so this PR's baseline measurements can inform retry tuning.
- **Streaming SCE.** Anthropic streaming is force-disabled for writing-style requests; the rest stay unchanged. A "stream + SCE" hybrid that evaluates on the full buffered text after the stream completes is a v1.50.4 concern.

## Verification

Smoke tests (run against the deployed worker, `cv-proxy.karp-gabriel-a.workers.dev`):

1. **OpenAI / Mistral / Gemini path.** Pick any active style + a Danish banned word. Trigger an AI generation. Response headers should include `X-AntCV-Sce-Banned-Words`, `X-AntCV-Sce-Banned-Phrases`, `X-AntCV-Sce-Clean`. If the LLM happened to use the banned word, `Sce-Clean: 0` and the count reflects the hit.
2. **Anthropic path.** Same test against an Anthropic model. The response now arrives as buffered `application/json` (not SSE) when a writing-style is active. PWA must handle both — it already does via `wrappedFetch`, but worth eyeballing the dispatcher breadcrumbs.
3. **ATS conversion.** Toggle `ats:true` in the request (currently hardcoded `false` in the fetch wrap; v1.50.3 will surface the toggle). Any `☎ ✉ 🔗 ⌂ ★` in the LLM output gets converted to plain-text labels, and `X-AntCV-Ats-Applied: 1` is set.
4. **Analytics.** In the Cloudflare dashboard → cv-proxy → KV → `ANALYTICS`, look for `writing-engine:<ts>:<id>` keys with `kind: 'sce-eval'`. Compare counts to the `kind: 'writing-engine'` (selection) events — there should be roughly one of each per LLM call.

Local smoke test (run from repo root):

```bash
node -e "
import('./workers/proxy/src/writing-style-engine.js').then(m => {
  const req = m.parseWritingStyleRequest({writingStyle:'achievement-driven',ats:true,target_language:'en'});

  const r = m.postProcessLlmResponse({data:JSON.stringify(fake),shape:'openai_compat',writingStyleRequest:req,env:{},userId:'t',augTask:null});
```

Expected output:

- Text has `Phone:` in place of `☎`.

## Risk

- **Anthropic streaming change.** Writing-style-active calls to Anthropic now arrive as `application/json` rather than `text/event-stream`. The PWA's `wrappedFetch` reportedly handles both. If any code path depends on SSE specifically for live token streaming, it'll see the full response in one chunk. Mitigation: only writing-style-active calls are affected; non-writing-style Anthropic calls still stream.
- **Response body parsing.** The post-process helper wraps a try/catch around the JSON parse. On parse failure the response passes through unchanged and a `console.warn` is logged. No request is ever blocked by this code path.
- **Analytics KV writes.** Every writing-style call now generates **two** KV writes (selection + SCE eval). KV is rate-limited per worker; current call volume is comfortably under. Document in `docs/qa/v1.50.2-status-report.md` for future scale-up.
