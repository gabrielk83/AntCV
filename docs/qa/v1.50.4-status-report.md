# v1.50.4 — PWA ATS toggle UI

**Plan citation:** AntCV_Plan_v2_LockedSources.md §8.6 + §4.10 — user-controlled ATS-safe export.
**Branch:** `feat/v1.50.4-ats-toggle` (stacked on `feat/v1.50.3-sce-retry`).
**Build version:** `1.50.4`.

## What this PR does

Before this PR, the fetch wrap (`src/lib/install-fetch-wrap.ts`) hardcoded `ats:false` on every outgoing `_antcv_writing_style` payload. The worker's ATS preamble note + glyph-conversion code (live since v1.50.1 / v1.50.2) had no user-facing way to turn on. This PR adds:

- `src/lib/export-prefs.ts` — `personalInfo.exportPrefs.{ats, legacyAtsTier}` read / write helpers + `antcv:export-prefs-changed` CustomEvent for cross-tab sync.
- `src/islands/ExportOptions/ExportOptionsCard.tsx` — two-toggle UI card mounted between WritingStylePicker and PackagePicker in Settings → Personal.
  - **ATS-safe generation** — toggles `personalInfo.exportPrefs.ats`. Worker adds an ATS-mode hint to the system preamble and runs `applyAtsGlyphConversion` on the LLM output.
  - **Legacy ATS tier** — toggles `personalInfo.exportPrefs.legacyAtsTier`. Stored for future use; v1.50.5 will wire this to "force Calibri body" on the DOCX worker when the user targets legacy parsers (Taleo pre-2018, iCIMS pre-2018, older SuccessFactors).
- `src/lib/install-fetch-wrap.ts` — reads `exportPrefs.ats` instead of the hardcoded `false`.

End-to-end:

1. User opens Settings → Personal, ticks "ATS-safe generation".
2. Selection persists to `personalInfo.exportPrefs.ats = true`.
3. On the next AI-generation call, fetch wrap injects `ats: true` into the `_antcv_writing_style` payload.
4. Proxy worker's `buildStyleSystemPreamble` adds an "ATS-safe mode: ON — convert glyphs to plain-text labels, force Calibri, single column, no photo" line to the system content.
5. Worker's `executeSceWithRetry` calls `applyAtsGlyphConversion` on the final draft, replacing `☎ ✉ 🔗 ⌂ ★` with `Phone: Email: Link: Location: Highlight:`.
6. Response carries `X-AntCV-Ats-Applied: 1` header so the PWA can show "ATS conversion applied" in observability surfaces.

## What this PR does NOT do

- **legacyAtsTier wiring.** Stored but not yet consumed by the worker or the DOCX renderer. v1.50.5 will wire it to "force Calibri body on DOCX export when legacy" via the docx-worker.
- **Per-export toggle.** ATS is currently a per-user / per-session preference. A more granular per-export toggle ("export this CV as ATS-safe but keep generation visual") is a v1.51 concern.
- **PWA observability.** Reading `X-AntCV-Ats-Applied` from response headers and surfacing it in the dispatcher breadcrumbs is a small follow-up — see "Follow-up" below.

## Verification

After PWA deploys (Cloudflare Pages auto-deploys from main when this PR merges):

1. Settings → Personal — the "Export options" card sits between WritingStylePicker and PackagePicker.
2. Tick "ATS-safe generation". DevTools console: `JSON.parse(localStorage.personalInfo).exportPrefs` → `{ ats: true, legacyAtsTier: false }`.
3. Trigger any AI generation. Network tab → outgoing request body's `_antcv_writing_style.ats` is `true`.
4. Response headers include `X-AntCV-Ats-Applied: 1` if the output contained any of the convertible glyphs (☎ ✉ 🔗 ⌂ ★). LLM output text shows `Phone:`, `Email:`, etc. in place of glyphs.
5. Untick ATS — next generation flows through with `ats:false`, no conversion, no `X-AntCV-Ats-Applied` header.

## Follow-up

- **PWA observability:** Add a small "SCE attempts: N · ATS-applied: yes" line to the dispatcher breadcrumbs panel reading from the response headers (`X-AntCV-Sce-Attempts`, `X-AntCV-Sce-Clean`, `X-AntCV-Flagged`, `X-AntCV-Ats-Applied`).
- **legacyAtsTier wiring (v1.50.5):** When `true`, DOCX worker forces Calibri body regardless of the active package's `bodyFont`.
- **Per-export toggle (v1.51):** Differentiate "generate with glyphs, export ATS-safe" from "generate ATS-safe end-to-end".
