# v1.50.5 — PWA observability layer

**Plan citation:** v1.50.1 / .2 / .3 follow-up. Surfaces the `X-AntCV-*` headers the proxy worker started emitting.
**Branch:** `feat/v1.50.5-pwa-observability` (stacked on `feat/v1.50.4-ats-toggle`).
**Build version:** `1.50.5`.

## What this PR does

Adds a small read-side observability tap to `src/lib/install-fetch-wrap.ts`. Every proxy response that carries any of our writing-engine headers is recorded into a circular buffer (last 50 entries) accessible via `window.AntcvObservability`, and dispatched as an `antcv:writing-engine-response` CustomEvent that any future PWA breadcrumbs panel can subscribe to.

When the localStorage flag `antcv:observability-verbose=1` is set, each entry is also pretty-printed to the console with the prefix `[antcv-observability]`. The default state is silent — the buffer + CustomEvent always populate but nothing prints unless verbose is on.

## What gets captured

For each writing-engine response (detected via presence of `X-AntCV-Writing-Style`, `X-AntCV-Sce-Clean`, `X-AntCV-Sce-Attempts`, or `X-AntCV-Task`):

| Field | Source header | Meaning |
|---|---|---|
| `ts` | client clock | When the response landed |
| `url` | request URL | Origin + pathname, query stripped |
| `status` | response | HTTP status |
| `task` | `X-AntCV-Task` | Augmentation task name (cv_outcomes, cl_what_i_bring, …) |
| `writingStyle` | `X-AntCV-Writing-Style` | Active style id |
| `targetLanguage` | `X-AntCV-Target-Language` | `en` / `da` / `es` / `zh` |
| `toneChips` | `X-AntCV-Tone-Chips` | Comma-split chip names |
| `sceBannedWords` | `X-AntCV-Sce-Banned-Words` | Banned-word hit count (final draft) |
| `sceBannedPhrases` | `X-AntCV-Sce-Banned-Phrases` | Banned-phrase hit count (final draft) |
| `sceClean` | `X-AntCV-Sce-Clean` | `true` when zero hits remain after retry |
| `sceAttempts` | `X-AntCV-Sce-Attempts` | 1 / 2 / 3 — number of LLM calls |
| `flagged` | `X-AntCV-Flagged` | `true` when third draft still dirty |
| `atsApplied` | `X-AntCV-Ats-Applied` | `true` when worker ran glyph→label conversion |
| `sanitizedPatterns` | `X-AntCV-Sanitized-Patterns` | Injection-defense redactions |

## Usage from DevTools

```js
// Recent activity:
window.AntcvObservability.readBuffer()
  .slice(-5)
  .map(e => ({ style: e.writingStyle, lang: e.targetLanguage, attempts: e.sceAttempts, clean: e.sceClean, flagged: e.flagged, ats: e.atsApplied }));

// Turn on console logging for the rest of the session:
window.AntcvObservability.setVerbose(true);

// Clear the buffer:
window.AntcvObservability.clearBuffer();

// Subscribe to live events:
window.addEventListener('antcv:writing-engine-response', e => console.log(e.detail));
```

## Use cases this unlocks

1. **§8.4 release-gate test prep.** Once analytics has a week of data, query `sceAttempts > 1` to compute retry rate per (style × language) cell. Cross-check against the server-side ANALYTICS KV entries.
2. **Dispatcher breadcrumbs.** A future PWA panel can subscribe to `antcv:writing-engine-response` and render the chain of generations the user has just triggered — style + chips + retry count + flagged.
3. **Live debugging.** When a user reports "the output keeps using the word X", we ask them to `setVerbose(true)` and reproduce — the console shows whether SCE caught it (and which retry attempt).

## Risk

- **Buffer growth.** Capped at 50 entries; oldest is discarded on overflow. Memory cost is negligible.
- **Header presence.** The detection uses 4 headers (`X-AntCV-Writing-Style`, `X-AntCV-Sce-Clean`, `X-AntCV-Sce-Attempts`, `X-AntCV-Task`). If a proxy response only carries `X-AntCV-Task` (non-writing-style augmentation path), it's still recorded — by design, since `task` is observability-relevant. Non-proxy fetches (CDN assets, etc.) carry none of these and are silently skipped.
- **CustomEvent loop.** The event fires on every recorded response. Subscribers must avoid making outgoing fetches in their handler or they'd re-trigger. The current code has no subscribers — safe.

## Follow-up

- **Dispatcher breadcrumbs UI.** A small island that subscribes to `antcv:writing-engine-response` and renders the recent chain alongside the existing `X-AntCV-Task` breadcrumb (wherever that already surfaces — probably in `pwa/app.js`'s existing debug panel).
- **§8.4 sample run.** Now that we have both server-side analytics (KV `writing-engine:<ts>` events) and client-side observability (this PR), we can run the §8.4 measurement after ~1 week of natural usage and compare server vs client tallies.
