## What this PR does

Removes the `<script src="antcv-stability-core-334.js?v=1.50.0-pass1" defer></script>` tag from `pwa/index.html` line 596. The file itself remains on disk under `pwa/antcv-stability-core-334.js` as audit trail; re-adding the script tag is a one-line revert if any of the four ported behaviours regresses.

This closes the last open Pass 1 exit criterion. The React islands have been the primary owners of LanguageCard / PreviewToolbar / SettingsRouter / wizardState behaviour since the Pass 1 PR merged; stability-core has been opt-out via `localStorage.setItem('antcv:disable-stability-core-334','1')` since then, giving you a verification toggle.

## Behaviours that go away

When stability-core stood down (toggle on) or when it's unloaded entirely (this PR), four secondary behaviours that lived alongside the main four P0s also stop running. Most are intentional improvements:

| Behaviour | Plan disposition | Net effect |
|---|---|---|
| `raiseSettings()` z-index ramp to `2147483200` on Settings modal | **Intentional removal** per Pass 1 exit "Zero `z-index: !important` over `--z-overlay-max`" | Settings modal now stays at the canonical `--z-overlay-max`. AI notice (z=`2147483300`) correctly sits above Settings — the original ramp was a workaround for the ramped Settings sitting above the AI notice. |
| `nonSettingsModalOpen()` selector check for `.antcv-ai-notice-host` etc. | Never read after the ramp goes — purpose served | No-op |
| Click delegation for "Open in Settings →" in Application history | Replaced by `useModalNav()` in `<SettingsRouter />` | Same behaviour through React |
| Button text replacement "User" → "Personal" in Settings tabs | Cosmetic; not ported | Settings might show "User" subtab label again if `app.js` hasn't been updated |
| Document-level `MutationObserver` on `document.documentElement` | **Intentional removal** per Pass 1 exit | Zero observers on documentElement from this file. |

If the "User → Personal" cosmetic rename matters, it's a 1-line fix in app.js (which would normally be a separate small PR; flagged here as a known minor visible difference).

2. Bump `?v=` and `sw.js` `CACHE` to invalidate the SW.
3. Deploy.
