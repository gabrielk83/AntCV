# v1.50.7 — C2PA watermark colour tracks the active package's `base` token

**Plan citation:** AntCV_Plan_v2_LockedSources.md §3 (package registry) + §9.3 (C2PA worker — "Watermark colour tracks the active package's `base` token via the request payload. No structural change.").
**Branch:** `feat/v1.50.7-c2pa-package-base` (stacked on `feat/v1.50.6-stability-core-deletion`).
**Build version:** `1.50.7`.

## What this PR does

Extends the C2PA signing worker's `SignRequest` schema with an optional `visual` field that carries the active package identifier and its `base` colour token. When present, the values are embedded in the `com.antcv.ai_disclosure` assertion of the C2PA manifest. Downstream verifiers can read the visual context alongside the AI-generation event, and a future visual watermark renderer pulls the same colour the document uses.

The field is **optional and backward-compatible** — existing PWA versions that don't send `visual` still work unchanged. A non-hex `package_base_color` is silently dropped (with a `console.warn` for debugging).

## Worker-side change only

This PR doesn't touch the PWA call site. The PWA's existing c2pa-worker invocation (in `pwa/app.js`) doesn't yet pass `visual.*`, so the manifest's `visual` field will read `null` until the PWA wiring lands. That wiring is the v1.50.8 follow-up — either a small fetch-wrap addition (similar to the writing-style injection from v1.50.1) or a direct call-site update in `app.js`.

## Risk

- **Schema additivity.** The `visual` field is optional and never mutates other manifest assertions. Old PWAs that don't send it still produce identical manifests minus the `visual` key.
- **Hex validation.** `normaliseHexColor` rejects anything not exactly `#RRGGBB`. Future package additions with different colour-format requirements (e.g. RGBA) need to extend the helper.
- **Worker still a scaffold.** The actual C2PA WASM signing is not yet wired (per existing README §2). The manifest preview path is the only execution path that runs today; this PR's change shows up in `manifest_preview.assertions[].data.visual`.

## Follow-up

- **v1.50.8 — PWA c2pa fetch wrap.** Add a small interceptor that detects POSTs to the c2pa-worker hostname (read from `relay-config.json` or wrangler config) and injects `visual.package` + `visual.package_base_color` from the active `personalInfo.stylePackage` and `PACKAGES[id].base` lookup.
- **DOCX worker palette wiring.** Larger separate PR — `workers/docx-worker` (~4000 lines) reads `packages/registry.json` and emits per-package OOXML colours.
- **Visual watermark renderer.** Once the WASM signing is wired, the document watermark stamp can read `manifest.assertions[].data.visual.package_base_color` to pick its tint.
