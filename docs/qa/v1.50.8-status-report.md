# v1.50.8 — DOCX worker palette wired to packages/registry.json + legacyAtsTier

**Plan citation:** AntCV_Plan_v2_LockedSources.md §3 (visual package registry) + §7 Pass 2 step 8 (DOCX worker — "Replace every hex literal in the DOCX worker with token reads from `packages/registry.json`. The worker bundles the registry read-only.").
**Branch:** `feat/v1.50.8-docx-palette` (stacked on `feat/v1.50.7-c2pa-package-base`).
**Build version:** `1.50.8`.

## What this PR does

Wires the DOCX worker's palette to the seven locked visual packages from `packages/registry.json`. Selecting Warm Terracotta in the PackagePicker now produces a Warm Terracotta DOCX (with its terracotta head band, Georgia headings + body), Tokyo Precision produces a charcoal DOCX with Tahoma headings, and so on across all seven packages.

Also wires the v1.50.4 `legacyAtsTier` toggle end-to-end: when on, the worker forces Calibri for the body font regardless of the active package's `bodyFont`. Legacy parsers (Taleo pre-2018, iCIMS pre-2018, older SuccessFactors) can extract the text without face-table issues.

## Architecture

The DOCX worker had its palette in a single `DEFAULTS` constant block at the top of `workers/docx-worker/src/generate.js` (lines 64-94). Every renderer in the worker reads from `style.<key>` where `style` is the merge of `DEFAULTS` and `payload.style`. So instead of touching 2700 lines of `generate.js`, this PR adds one new file (`palette.js`) and tweaks `mergeStyle()` to use it.

```
                                  ┌───────────────────────────────┐
PWA personalInfo.stylePackage  ───▶  pwa/antcv-docx-client.js     │
PWA personalInfo.exportPrefs   ───▶    readPackageId()            │
       .legacyAtsTier                  readLegacyAtsTier()         │
                                  ─── package, legacy_ats_tier ───▶
                                  ┌───────────────────────────────┐
                                  │  workers/docx-worker          │
                                  │    palette.js                 │
                                  │      getPackageStyle(id, leg) │
                                  │        ↓                      │
                                  │    generate.js mergeStyle()   │
                                  │      ← payload.style overrides│
                                  │        ↓                      │
                                  │    OOXML render with style.*  │
                                  └───────────────────────────────┘
```

## Backward compatibility

`mergeStyle(input, packageId, legacyAtsTier)` falls back to the legacy `DEFAULTS` when `packageId` is absent or empty. Pre-v1.50.8 PWAs (which don't send `package`) keep producing exactly the documents they did before — same palette, same fonts, same colours.

v1.50.8+ PWAs send `package` on every DOCX request. The worker derives its palette from `packages/registry.json` via `palette.js`. `payload.style` overrides still win over the package-derived base, so any explicit colour the PWA sends (e.g. via the legacy `navyColor` fallback in `buildStyle`) is preserved.

## Behavioural delta — Copenhagen Modern (the default package)

The locked registry differs from the legacy DEFAULTS for Copenhagen Modern. After v1.50.8 deploys, an existing user's Copenhagen Modern export changes as follows:

| Field | Legacy DEFAULTS | v1.50.8 Copenhagen Modern | Note |
|---|---|---|---|
| `mainHeadColor` | `1B627F` (desaturated teal) | `283556` (navy) | Matches the PWA preview's `--main-head-color` |
| `mainBulletColor` | `1B627F` | `00746E` (teal) | Matches `--package-bullet` |
| `headerBg` | `1B627F` | `283556` | Matches the candidate-info band on the preview |
| `tableHeaderBg` | `1B627F` | `283556` | Same as headerBg |
| `sidebarHeadColor` | `01B7BB` (bright teal) | `00746E` (deeper teal) | Matches `--package-primary` |
| `photoBorderColor` | `01B7BB` | `00746E` | Same as sidebarHeadColor |
| `mainHeadFont` | `Trebuchet MS` | `Segoe UI` | Plan §3.1 Option A — locked decision |
| `sidebarFont` | `Trebuchet MS` | `Segoe UI` | Same |
| `headerFont` | `Trebuchet MS` | `Segoe UI` | Same |

This is the intended migration. The PWA's preview has been showing the registry palette since Pass 2 (v1.50.0-pass2); v1.50.8 brings DOCX exports in line.

If a user explicitly wants the legacy look, they can use the PackagePicker's Custom mode to override individual colours / fonts; those overrides flow through via `payload.style` and win over the package base.

## Risk

- **Existing user palette change.** Copenhagen Modern's head colour shifts from `1B627F` to `283556`, heading font from Trebuchet MS to Segoe UI. This is the locked v1.50 migration per plan §3.1 Option A and matches the live preview. Documented in the behavioural-delta table above. Users who explicitly want the prior look can use Custom-mode overrides.
- **Body font availability.** Warm Terracotta uses Georgia (already system-default on Windows + Mac + most Linux distros). The other six packages use Calibri body. No new font dependencies.
- **Worker schema looseness.** `schema.js` is permissive — `package` and `legacy_ats_tier` aren't validated explicitly. `palette.js` defensively normalises (unknown → copenhagen-modern; non-string → false). Worst case: a malformed `package` value silently falls back to Copenhagen Modern.
